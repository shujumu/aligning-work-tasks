# Aligning Work Tasks

一个面向职场任务交接的 Codex Skill。它把零散、模糊或互相冲突的要求整理成最小任务契约、可勾选步骤、证据要求、状态判断和可直接提交的汇报。

它适合任务接收者、任务下达者和验收者，不限定 ERP 实施岗位。仓库内置 ERP、新媒体、软件、销售、财务、客服、工程、医疗、人力、采购与法务等领域视角。

## 它解决什么

- 区分事实、信息缺口、冲突和暂定假设。
- 明确目标、范围、排除项、权限、截止时间、交付物和验收标准。
- 把工作项拆成带稳定编号的 Markdown 复选框步骤。
- 检查身份、条件、操作、结果和验收五类证据。
- 在证据不足时输出具体缺口，而不是猜测“已完成”。
- 生成任务表待应用增量和面向上级的简洁汇报。

它不会代替组织审批，也不会仅凭一段对话自动登录系统、修改生产数据、付款、发布内容或对外发送消息。

## 安装

将 [`skills/aligning-work-tasks`](skills/aligning-work-tasks) 整个目录放入 Codex 的个人 Skill 目录。

Windows PowerShell：

```powershell
Copy-Item -Recurse -Force .\skills\aligning-work-tasks "$env:USERPROFILE\.codex\skills\aligning-work-tasks"
```

macOS / Linux：

```bash
cp -R ./skills/aligning-work-tasks ~/.codex/skills/aligning-work-tasks
```

重新打开 Codex 任务后，显式调用：

```text
使用 $aligning-work-tasks 对齐这项工作，指出关键信息缺口并生成可执行、可验证的交接结果。
```

## 第一次使用

尽量一次提供以下材料；没有的内容可以明确写“不确定”：

- 上级的原始消息和后续补充，不要只给自己的转述。
- 现有任务表、旧版交接记录、项目或事项编号。
- 已知的目标、截止时间、执行环境、权限和验收口径。
- 已完成步骤、阻塞项，以及经过脱敏的证据图片或文件。

首轮提示词：

```text
使用 $aligning-work-tasks 处理下面的原始任务。
先分离事实、缺口、冲突和假设，再判断哪些能直接做、哪些只能准备、哪些必须先确认。
输出：给上级的对齐消息、按事项编号的可勾选步骤、证据清单和表格字段增量。
原始任务：……
```

常见输出包括：对齐消息、最小任务契约、执行清单、证据检查、四态结果、待应用表格增量和向上汇报。任务很清晰且风险低时，Skill 应直接给出简洁执行结果，不强行展开全部模板。

## 如何提供图片证据

图片要足够证明结论，但不要无差别堆图。

- 查询或复测任务优先成对上传“查询条件图 + 结果图”。
- 使用稳定编号命名，如 `P01-I02-condition.png`、`P01-I02-result.png`。
- 保留能识别项目、对象、环境、时间和结果的区域，裁掉无关界面。
- 上传前遮挡密码、令牌、验证码、个人信息、客户资料、银行信息和仅限生产环境的标识。
- 密码或令牌已经出现在聊天或图片中时，不要再次粘贴；通知负责人通过授权渠道撤销或轮换。
- 一张图片无法同时证明条件和结果时，明确告诉 Skill 缺少哪一张，不要要求它“根据经验判断”。

## 如何持续跟进

- 一个持续任务尽量保留在同一个 Codex 对话中；新对话不会自动拥有未重新提供的状态。
- 不要更改既有事项编号。新增事项使用新编号，范围变化时说明“原要求、变化、影响”。
- 每轮只汇报本次新增完成、状态变化、阻塞变化和新证据。
- 附上新的条件图、结果图或文件路径，并要求 Skill 检查证据充分性。
- 每轮结束要求输出“待应用表格增量”；只有实际获得可写工具和授权后，才能声称表格已更新。

进度提示词：

```text
继续使用 $aligning-work-tasks。保留现有事项编号。
本轮变化：……
新增证据：……
请重新判定受影响事项，只输出状态变化、证据缺口、待应用表格增量和给上级的最新汇报。
```

## 三个使用示例

### 1. 接收模糊任务

```text
使用 $aligning-work-tasks 对齐领导发来的消息：“把上周那些问题再查一下，表更新后发我。”
我只有一份旧表和几段聊天记录。请先指出最多三个真正阻塞的问题；能安全准备的先列清单，但不要假设项目、环境或修改权限。
```

预期：Skill 先确认对象、范围/时点、环境与权限，生成按编号的核验步骤和“条件图 + 结果图”要求；不会在没有写入工具时声称已经更新旧表。

### 2. 清楚地下达任务

```text
使用 $aligning-work-tasks 检查我准备发给实习生的任务：
目标：把本周一至周三的三份会议纪要按日期合并。
范围：只合并正文并修正明显错别字，不润色、不发送邮件。
输入：共享盘“周会资料”中日期对应的三个文件。
交付：今天 17:00 前保存为“第30周会议纪要汇总.docx”，仍放在原文件夹。
验收：日期顺序正确、三份内容完整、原文件不修改。
请指出仍缺少的关键内容；如果已足够，直接生成简洁可执行清单，不要额外制造审批步骤。
```

预期：这是清晰、低风险、可逆的任务，Skill 应直接形成短清单。

### 3. 验收返回证据

```text
使用 $aligning-work-tasks 验收 P01-I01。
验收标准：在确认环境和日期条件下查询结果为“成功”。
执行者只上传了一张显示“成功”的结果图，没有查询条件、环境或对象编号。
请判断证据是否足够，列出具体缺口，并生成可直接回复执行者的补充材料要求。
```

预期：状态为“无法验证”，不是“已恢复”；补充要求应指向对象身份、环境、日期/筛选条件和与结果图配对的条件图。

## 安全边界

- 外部发布、生产修改、付款、删除、权限变更、合同承诺和敏感数据处理必须得到明确授权。
- “没有回复”不等于批准，除非组织已有明确、有效且适用于本次任务的书面规则。
- 医疗、财务、法律和人事判断必须由有资质或有权限的人员复核。
- Skill 可以整理增量，但不能在没有工具记录时声称已保存、已发送、已发布或已更新。
