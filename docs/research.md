# 跨行业任务交接调研

调研日期：2026-07-28

## 结论

各行业使用的名词不同，但有效交接反复出现同一组结构：明确对象与目标、固定输入版本、界定范围和权限、指定责任与时限、提前定义验收标准、用可追溯证据记录结果、对例外和变化保留状态。

本项目把这组共同结构称为“最小任务契约”。它不是要求所有工作都填一张大表，而是只补充会改变执行、风险或验收结论的信息。清晰且低风险的任务直接执行；可安全准备的任务先完成无副作用部分；不可逆或高风险动作等待明确授权。

## 调研方法与边界

本调研使用公开的产品文档、行业工作方法和一篇同行评议系统综述，结合用户提供的匿名 ERP 实施交接案例做结构对比。它是面向 Skill 设计的实践性综合，不是对所有行业组织的统计抽样，也不把某个产品页面视为行业强制标准。

## 跨行业观察

| 场景 | 公开做法中的结构 | 信息失真的典型后果 | 本项目的对应设计 |
| --- | --- | --- | --- |
| 新媒体与创意工作 | Creative brief 预先集中目标、受众、信息、交付物、时间等上下文 | 素材版本、价格、版权或审批口径混杂 | 素材版本与授权字段；外部发布门禁；沉默不等于批准 |
| 软件开发与测试 | GitHub Issue Forms 用结构化输入、下拉选项、复选框和必填校验收集问题信息 | 复现条件、环境、期望结果或完成定义缺失 | 最小任务契约；按事项编号的步骤；条件、结果和验收证据 |

## 共性问题

### 1. 上级表达的是意图，下级需要的是执行条件

“尽快核一下”“更新原来的表”“发两个平台”等话语表达方向，却常缺少对象、版本、范围、权限和验收口径。执行者若用自己的经验补齐，速度可能更快，但会把个人假设写进交付结果。

解决方式不是无限追问，而是只问会改变结果的高价值问题，并将其余不确定项标记为假设。最多三个阻塞问题是一种输出约束，不意味着复杂任务永远只允许确认三次。

### 2. 状态词相同，背后的证据并不相同

“完成”“修复”“发布”可能只表示做过操作，也可能表示结果已通过验收。缺少预先约定的完成定义时，执行者和验收者容易使用不同口径。

本项目要求证据覆盖身份、条件、操作、结果和验收。问题复测使用“已恢复、仍存在、部分恢复、无法验证”；普通任务映射为“已完成、未完成、部分完成、无法验收”。证据不足必须保留为无法判断，而不是并入失败或成功。

### 3. 任务在变化，表格却常被当成静态结果

软件 Issue、工程 RFI、财务关账任务和 ERP 问题表都需要稳定编号、责任、状态和历史。范围中途变化时，直接覆盖旧要求会丢失决策依据。

因此 Skill 保留事项编号，记录“原要求、变化、影响”，每轮只生成字段级增量。只有工具和授权确实允许写入时才更新原载体。

### 4. 高风险动作不能依赖沉默或模糊授权

内容发布、生产修改、付款、施工、诊疗和合同承诺的共同点是会影响外部主体或难以撤回。时间压力不会降低授权要求。

Skill 将工作分为“可直接执行、准备后确认、必须先确认”三类。没有回复时仍可完成草稿、只读查询和清单等无副作用准备，但不能把沉默解释为发布或修改许可。

## 岗位解决方案摘要

- ERP 实施：固定项目编号、产品/环境、组织或账套、模块、补丁版本、查询时点和回归证据。
- 新媒体运营：固定平台账号、受众、素材与文案版本、价格生效口径、版权授权、审批和指标窗口。
- 软件研发测试：固定仓库/提交、环境版本、复现步骤、期望与实际结果、测试和发布范围。
- 销售：固定客户/机会、阶段、需求、报价权限、承诺、责任人和下一动作。
- 财务：固定主体、期间、账套、数据源、差异阈值、制表/复核责任和审计证据。
- 客服：固定工单、身份核验、诉求、政策版本、已做操作、升级原因和 SLA。
- 工程：固定位置、图纸版本、专业、现场条件、RFI、影响、批准和复验照片。
- 医疗：按 SBAR/ISBAR 组织最小必要信息，强调紧急升级、回读和专业人员确认。
- 人力：固定岗位/编制、硬性条件、结构化筛选、阶段、审批和候选人隐私。
- 采购与法务：固定对象、文件版本、预算或授权、条款偏差、审批链和签署版本。
